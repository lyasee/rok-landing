## 2. 앱이 기기 안에서 처리하는 정보

이용자가 포근일기를 사용할 때 다음 정보는 앱 기능을 제공하기 위해 이용자의 기기 안에서 처리됩니다.

| 처리 항목                                                      | 이용 목적                     | 기본 저장 위치             |
| -------------------------------------------------------------- | ----------------------------- | -------------------------- |
| 일기 날짜, 제목, 글                                            | 일기 작성, 달력·검색 표시     | 앱의 기기 내 SQLite 저장소 |
| 이용자가 선택한 사진과 앱이 관리하는 사진 파일                 | 일기 편집과 표시              | 앱의 기기 내 파일 저장소   |
| 스티커 즐겨찾기, 스티커·속지 선택, 위치, 크기, 회전, 앞뒤 순서 | 한 페이지 편집 상태 저장·복원 | 앱의 기기 내 저장소        |
| 휴지통 기록과 복원 상태                                        | 실수로 삭제한 일기 복원       | 앱의 기기 내 저장소        |
| 앱 설정과 잠금 사용 여부                                       | 이용자가 고른 환경 유지       | 앱 설정은 기기 내 SQLite, 잠금 사용 여부는 기기 내 SecureStore |
| 기존 버전에서 이전된 로컬 복구 사본                            | 저장 구조 이전과 복구 지원     | 기존 기기의 AsyncStorage에 남을 수 있음 |

포근일기는 현재 회원가입, 광고 추적 SDK, AI 처리, 운영자 서버를 통한 일기 동기화를 제공하지 않습니다. 앱은 일기 내용이나 사진을 운영자 서버로 자동 전송하지 않습니다. 이는 앱 밖에서 별도로 이루어지는 고객지원 이메일, 앱 스토어 처리, 기기·운영체제 백업 또는 웹사이트 접속 로그까지 아무 정보도 처리되지 않는다는 뜻은 아닙니다.

네이티브 앱에서 현재 사용되는 일기 상태의 기준 저장소는 SQLite이며, 사진은 앱 전용 파일 저장소에 보관됩니다. 기존 저장 구조의 기록은 앱 업데이트 과정에서 로컬 SQLite로 이전될 수 있고, 이 과정은 이용자의 기기 안에서 수행됩니다. 기존 버전에서 읽은 AsyncStorage 값은 이전이 성공한 뒤에도 비권위적인 복구 사본으로 기기에 남을 수 있으며, 이후 정상적인 일기 표시·저장에는 사용되지 않습니다. 앱 안의 개별 삭제나 휴지통 비우기가 이 이전 사본까지 삭제하지 않을 수 있으므로, 해당 사본을 없애려면 앱 데이터 초기화 또는 앱 삭제가 필요할 수 있습니다.

웹 미리보기는 네이티브 앱과 저장 방식이 다릅니다. 웹 브라우저의 IndexedDB에 기록을 저장하고, 선택한 사진은 브라우저 안의 상태에 data URL 형태로 포함할 수 있습니다. 웹 미리보기의 저장 내용도 운영자 서버로 자동 전송되지 않습니다.

## 3. 사진 접근과 선택적 시스템 인증

이용자가 사진 추가 기능을 선택하면 운영체제가 제공하는 사진 선택 절차를 사용합니다. 이용자가 고른 사진만 일기 편집에 사용되며, 선택한 사진은 앱 전용 저장소로 복사됩니다. 카메라나 마이크를 사용하는 기능은 없고, 필요한 사진 접근 권한은 기기 설정에서 변경할 수 있습니다.

네이티브 앱에서 잠금 기능을 켜면 운영체제의 기기 인증 화면을 사용할 수 있습니다. 얼굴·지문 등 생체정보의 등록·비교는 운영체제가 담당하며, 포근일기는 생체정보 자체를 수집하거나 저장하지 않습니다. 웹 미리보기에는 이 시스템 인증 잠금 기능이 없습니다.

정확히는 앱이 운영체제로부터 인증 가능 여부와 등록 상태의 요약값을 확인하고, 인증 과정에서는 성공·실패·취소·오류 등의 결과를 받습니다. 앱은 얼굴·지문 원본, 생체 템플릿 또는 생체 특징값을 받거나 저장하지 않습니다. 현재 공개 준비 빌드에서 확인되는 주요 권한은 iOS의 사진 보관함·Face ID와 Android의 인터넷·생체 인증·진동입니다. 카메라, 마이크, 일반 외부 저장소 읽기·쓰기 권한은 사용하지 않도록 구성되어 있습니다. Android 매니페스트에 `SYSTEM_ALERT_WINDOW`가 선언되어 있으나 현재 앱 기능에서 사용처가 확인되지 않았으므로 공개 전에 제거 또는 사용 목적 확인이 필요합니다.

## 4. 일기 삭제, 휴지통과 로컬 저장

일기는 이용자가 삭제하거나 앱 데이터 또는 앱을 삭제할 때까지 기기에 보관될 수 있습니다. 앱에서 삭제한 일기는 휴지통으로 이동하며, 이용자는 앱이 제공하는 범위에서 복원하거나 완전히 삭제할 수 있습니다.

앱을 삭제하거나 기기 데이터를 초기화하면 일기와 사진을 복구하지 못할 수 있습니다. 기존 버전에서 이전된 AsyncStorage 복구 사본이 있는 경우에는 앱 안에서 현재 일기를 삭제하거나 휴지통을 비우더라도 그 사본이 남을 수 있습니다. 앱 밖의 사진 보관함, 기기 백업, 이용자가 직접 내보낸 파일은 앱의 휴지통과 별개이므로 각 위치에서 직접 관리해야 합니다. 운영자는 앱이나 이용자 기기에만 있는 일기, 휴지통 기록 또는 백업 파일에 원격으로 접근하거나 대신 삭제할 수 없습니다.

## 5. 내보내기, 백업과 암호

이용자는 일기를 내보내거나 백업 파일을 만들고, 운영체제 공유 화면을 통해 저장할 위치나 받을 사람·앱을 직접 선택할 수 있습니다. 선택한 위치 또는 제3자 앱으로 전달된 뒤에는 해당 저장소나 서비스의 정책이 적용됩니다.

기본 백업 파일은 이용자가 정한 암호로 암호화됩니다. 백업 암호는 앱 또는 운영자가 저장하지 않으며, 잊어버린 암호를 복구해 드릴 수 없습니다. 암호화 백업은 **내보낸 백업 파일을 보호하는 기능**이며, 기기 안의 전체 SQLite 데이터베이스와 사진 파일을 앱 자체 방식으로 모두 암호화한다는 의미는 아닙니다.

이전 버전과의 호환을 위해 일반 JSON 백업을 읽을 수 있고, 이용자가 일반 JSON 형식으로 내보낼 수도 있습니다. 일반 JSON 파일에는 일기 날짜·제목·글, 사진, 편집 위치·크기·회전·순서, 즐겨찾기, 휴지통 기록과 생성·수정 시각 등 앱의 전체 기록 상태가 암호화되지 않은 채 포함될 수 있습니다. 일반 JSON은 보관 위치와 전달 대상을 이용자가 주의해서 선택해야 합니다. 암호화 또는 일반 백업 파일을 운영체제 공유 화면으로 전달하면 이용자가 선택한 메일·메신저·파일 저장 서비스가 파일을 별도로 보관하거나 처리할 수 있습니다.

## 6. 기기·운영체제 백업과 클라우드 동기화의 차이

포근일기는 운영자가 제공하는 계정 기반 클라우드 동기화 기능이 없습니다. 현재 Android 공개 준비 빌드에는 `allowBackup=false`가 적용되어 Android 자동 백업이 비활성화되어 있습니다. iOS의 기기·운영체제 백업은 Apple의 기기 및 계정 설정과 운영체제 정책에 따라 별도로 작동할 수 있으므로, 실제 포함 여부와 보유·삭제·복원 범위는 해당 시스템 정책을 확인해야 합니다.

이용자가 백업 파일을 공유하거나 가져오기 위해 iCloud Drive, Google Drive, 메일, 메신저 또는 다른 파일 제공자를 직접 선택하는 경우는 앱 자체 클라우드 동기화와 별개의 외부 서비스 이용입니다. 선택한 서비스의 정책에 따라 파일이 전송·보관될 수 있으며 운영자는 그 파일에 접근하지 않습니다. 운영체제 자동 백업과 이용자가 직접 선택한 외부 파일 저장은 모두 앱의 운영자 서버 동기화가 아닙니다.
